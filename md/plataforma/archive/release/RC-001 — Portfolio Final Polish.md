# Objetivo

O Portfolio entra oficialmente em fase de Release Candidate.

Nenhuma nova funcionalidade deverá ser criada.

Nenhuma nova arquitetura deverá ser proposta.

O objetivo exclusivo desta Sprint é elevar a percepção de qualidade do Portfolio até um nível compatível com um Principal Product Designer.

Todo o projeto deverá ser revisado criticamente.

---

# Mentalidade

Durante esta Sprint o Codex deixa de atuar como implementador.

Passa a atuar simultaneamente como:

- Product Designer Principal
- UX Lead
- Design Director
- Front-end Staff Engineer
- Recrutador Técnico
- Head de Produto

Cada alteração deverá responder:

"Isso melhora a experiência?"

Se não melhorar claramente, não deve ser implementado.

# Home

A Home deve comunicar em menos de 20 segundos:

Quem sou.

O que faço.

Por que sou diferente.

Como acessar um Case.

Nenhuma seção poderá parecer apenas "mais um bloco".

Cada seção deve possuir personalidade própria.

---

# Cases

Os Cards deverão parecer showcases de produto.

Jamais cartões de blog.

Cada Card deve despertar curiosidade.

---

# Página do Case

A leitura deve parecer uma publicação premium.

Não uma documentação.

Toda seção deve iniciar com forte hierarquia.

Todo bloco deve possuir ritmo visual.

Toda informação importante deve ser facilmente escaneável.

---

# Product Transformation Journal

O Journal deve parecer um laboratório de decisões.

Nunca um blog.

Nunca uma seção genérica.

O visitante deve entender imediatamente:

Cases mostram o resultado.

Journal mostra o raciocínio.

---

# Navegação

Verificar todos os fluxos.

Home → Case

Case → Home

Case → Journal

Journal → Home

Desktop

Tablet

Mobile

Nenhum fluxo poderá gerar dúvida.
