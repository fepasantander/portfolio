# Felipe Santander — Portfolio

# P05 — Design Language

Version: 1.0

Status: Approved

---

# Objetivo

Definir a linguagem visual do Portfolio.

Este documento não especifica CSS.

Não especifica Tailwind.

Não especifica componentes.

Ele define a experiência visual que deverá ser percebida pelo visitante.

Toda decisão de UI deverá obedecer estes princípios.

---

# Conceito

Menos Dribbble.

Mais Apple.

Menos Behance.

Mais Linear.

Menos decoração.

Mais comunicação.

O design deve desaparecer para que os Cases apareçam.

---

# Personalidade Visual

O Portfolio deve transmitir:

• Clareza

• Organização

• Maturidade

• Confiança

• Elegância

• Precisão

Nunca deve transmitir:

• Excesso de criatividade

• Efeitos gratuitos

• Interface "gamer"

• Visual acadêmico

• Interface corporativa pesada

---

# Hierarquia

A informação é mais importante que a interface.

A interface é mais importante que a decoração.

A decoração nunca é prioridade.

---

# Ritmo

Muito espaço em branco.

Leitura confortável.

Blocos bem separados.

Respiração visual.

Nada deve parecer apertado.

---

# Layout

Grid consistente.

Containers amplos.

Margens generosas.

Alinhamentos rigorosos.

Cards com altura coerente.

Nada desalinhado.

---

# Tipografia

Poucas variações.

Hierarquia forte.

Parágrafos curtos.

Títulos grandes.

Subtítulos discretos.

Texto fácil de escanear.

Evitar blocos extensos.

---

# Cores

A cor existe para orientar.

Nunca para decorar.

A interface deve funcionar mesmo quase monocromática.

Cor será utilizada para:

• CTAs

• Links

• Estados

• Feedback

Nunca para chamar atenção desnecessariamente.

---

# Ícones

Poucos.

Sempre lineares.

Mesmo estilo.

Mesmo peso visual.

Nunca misturar bibliotecas.

---

# Cards

Todos seguem o mesmo padrão.

Imagem

↓

Título

↓

Categoria

↓

Resumo

↓

Resultado

↓

CTA

Nada além disso.

---

# Cases

O Hero deve ocupar o protagonismo.

O restante da página deve conduzir naturalmente a leitura.

Grandes imagens.

Texto curto.

Resultados evidentes.

---

# Empresas

Logotipos discretos.

Mesma altura.

Mesmo peso visual.

Nunca competir com os Cases.

---

# Testimonials

Visual limpo.

Foto pequena.

Nome.

Cargo.

Empresa.

Texto.

Nada mais.

Os Testimonials comprovam.

Os Cases convencem.

---

# Journal

Visualmente relacionado ao Portfolio.

Mas claramente identificado como outro produto.

Pode utilizar um tratamento visual levemente distinto para reforçar a ideia de aprofundamento.

Nunca parecer uma propaganda.

---

# Botões

Poucos estilos.

CTA principal.

CTA secundário.

Link.

Nada além disso.

---

# Animações

Objetivo:

Guiar.

Nunca impressionar.

Transições curtas.

Fade.

Slide discreto.

Hover suave.

Nada que atrase a navegação.

---

# Scroll

Natural.

Sem efeitos parallax.

Sem narrativa baseada em scroll.

O conteúdo deve funcionar mesmo com rolagem rápida.

---

# Imagens

Sempre reais.

Sempre grandes.

Sempre nítidas.

Nunca utilizar mockups artificiais quando houver capturas reais do projeto.

Priorizar:

Produtos.

Fluxos.

Interfaces.

Processos.

Discovery.

Boards.

---

# Responsividade

Mobile First.

Desktop elegante.

Tablet tratado como extensão natural.

Nenhum componente exclusivo para desktop.

---

# Performance

Toda decisão visual deve respeitar:

Performance

SEO

Acessibilidade

Core Web Vitals

Nunca sacrificar desempenho por estética.

---

# Acessibilidade

Contraste adequado.

Foco visível.

Navegação por teclado.

Estados claros.

Alt text obrigatório.

Animações respeitando prefers-reduced-motion.

---

# Sensação Final

Ao fechar o Portfolio, o visitante deve pensar:

"Esse profissional resolve problemas complexos com simplicidade."

Não:

"Que site bonito."

O design é um meio.

Nunca o objetivo.
