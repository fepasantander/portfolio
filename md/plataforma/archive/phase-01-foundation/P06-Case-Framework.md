# Felipe Santander — Portfolio

# P06 — Case Framework

Version: 1.0

Status: Approved

---

# Objetivo

Definir um padrão único para todos os Cases publicados no Portfolio.

Todo novo Case deverá obedecer exatamente esta estrutura.

O objetivo é criar consistência visual, editorial e arquitetural.

O visitante deve conseguir navegar por qualquer Case sabendo exatamente onde encontrará cada informação.

---

# Filosofia

O Portfolio apresenta resultados.

O Journal apresenta o processo.

O Case existe para convencer.

O Journal existe para aprofundar.

---

# Tempo de leitura

Objetivo:

2 minutos

Máximo aceitável:

3 minutos

Caso ultrapasse esse tempo, o conteúdo deverá migrar para o Journal.

---

# Estrutura Obrigatória

Todos os Cases seguirão exatamente esta sequência.

Hero

↓

Resumo Executivo

↓

Contexto

↓

Problema

↓

Minha atuação

↓

Solução

↓

Resultados

↓

Galeria

↓

Stack utilizada

↓

CTA para Journal

↓

Próximo Case

---

# Hero

Obrigatório.

Componentes:

Imagem principal

Categoria

Empresa

Título

Resumo de uma frase

CTA

---

# Resumo Executivo

Máximo:

5 linhas

Responder:

O que foi desenvolvido?

Qual problema resolveu?

Qual foi meu papel?

---

# Contexto

Máximo:

2 parágrafos.

Explicar rapidamente:

Empresa

Produto

Momento

Objetivo

---

# Problema

Máximo:

3 bullets

Não contar toda a história.

Apenas o desafio principal.

---

# Minha Atuação

Mostrar claramente meu papel.

Exemplos:

UX Strategy

Discovery

UX Research

UI

Arquitetura

Design System

Front-end

Product Discovery

IA Generativa

Business Analysis

---

# Solução

Descrever somente a solução final.

Evitar narrativa longa.

Evitar cronologia.

---

# Resultados

Somente resultados comprovados.

Nunca estimativas.

Nunca métricas inventadas.

Caso não exista número validado:

descrever resultado qualitativo.

---

# Galeria

Obrigatória.

Tipos permitidos:

Interface

Fluxos

Boards

Discovery

Wireframes

Arquitetura

Protótipos

Nunca:

mockups decorativos

renders

stock photos

---

# Stack

Mostrar apenas tecnologias realmente utilizadas.

Agrupar por categoria.

Exemplo:

UX

Research

Prototipação

Analytics

IA

Front-end

---

# CTA

Sempre terminar com:

Explorar o Product Transformation Journal

ou

Vamos conversar

Nunca terminar sem ação.

---

# Navegação

Cada Case possui:

Anterior

Próximo

Voltar aos Cases

---

# Categoria

Cada Case pertence a uma categoria principal.

Exemplos:

IA Generativa

Educação

HealthTech

Fintech

Produtos Digitais

---

# Tags

Cada Case poderá possuir múltiplas tags.

Exemplo:

Discovery

UX

Research

AI

Figma

Métricas

Design System

Acessibilidade

---

# Dados Estruturados

Todos os Cases deverão utilizar um único modelo de dados.

Nenhuma informação deverá ser duplicada entre:

Home

Cards

Case

Journal

A Home deverá consumir o mesmo catálogo utilizado pelos Cases.

O Journal deverá referenciar o mesmo identificador.

---

# Relação com o Journal

Cada Case poderá possuir:

Journal disponível

ou

Sem Journal publicado.

Caso exista Journal:

mostrar CTA.

Caso contrário:

não criar placeholder.

---

# Critérios para Publicação

Um Case somente poderá ser publicado quando possuir:

✓ Nome

✓ Hero

✓ Resumo

✓ Problema

✓ Minha atuação

✓ Solução

✓ Resultado

✓ Imagens reais

✓ Stack

✓ Revisão

Caso qualquer item esteja ausente:

o Case permanece fora do Portfolio.

---

# Critérios de Aceite

✓ Todos os Cases seguem exatamente o mesmo padrão.

✓ Nenhum conteúdo é duplicado.

✓ Journal permanece complementar.

✓ Tempo médio inferior a 3 minutos.

✓ Hero consistente.

✓ CTA obrigatório.

✓ Navegação consistente.

✓ Estrutura preparada para crescimento futuro.
